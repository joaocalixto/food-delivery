Construindo um MCP no restaurant-service

Tudo o que preparamos para a aula de MCP num lugar só: o passo a passo do MCP, os dados de teste com 5 restaurantes, como rodar cada coisa e as perguntas para brincar com a IA.

Preparado em 31/10/2026 · repo joaocalixto/food-delivery (commit fa31c34) · Spring Boot 4.1 · Java 21 · Spring AI 2.0.1

A pergunta da aula “O MCP me dá um poder novo, ou só uma porta nova?” A resposta curta: uma porta nova. A ferramenta MCP chama a mesma regra de negócio que o REST. O que muda é quem chama: no REST é um programa que você escreveu; no MCP é uma IA que lê a descrição e decide sozinha.

Ordem sugerida

  1. Na véspera, quem dá a aula: troca o DataSeeder e recarrega o banco (09 e 10), e passa o checklist.
  2. Na aula, a turma: entende o MCP (03–05), constrói (06), roda e liga a IA (07).
  3. Depois: brincam com as perguntas e comparam com o REST (12).
O que ainda não foi testado O código (MCP e DataSeeder) está na main do GitHub (veio pelo PR #2). Os tipos foram conferidos com o código real do domínio e do serviço, e o YAML e o XML foram validados. Mas ele não foi compilado com as dependências reais do Spring AI, porque o ambiente onde foi feito não acessa o Maven Central. Rode uma vez antes da aula.
Corrigido nesta versão (1) No compose, o banco e o Redis do restaurant-service não abrem porta para o seu computador, então o serviço sobe pelo próprio compose (07). (2) Para recarregar os dados, apaga-se só o banco de restaurantes e o Redis, não todos os bancos (10). (3) A resposta “vegetariano em cada restaurante” ganhou os pratos que faltavam (11). (4) O código foi para a main do GitHub, junto com este caderno, na pasta caderno-mcp/.

03MCP em palavras simples

Estrutura igual à do curso “Introduction to Model Context Protocol” da Anthropic Academy. O curso usa Python; aqui usamos Spring AI, mas as ideias são as mesmas.

A ideia central. Para uma IA usar o restaurant-service, alguém teria que escrever à mão a descrição de cada ação: nome, parâmetros e o que faz. O MCP é um padrão para isso. Você coloca as ações num servidor MCP, e qualquer IA compatível lê a lista e usa. Escreve uma vez, vale para várias IAs.

Quem é quem

  • Servidor MCP: o seu serviço, que oferece as ações. Aqui é o restaurant-service, no endereço /mcp.
  • Cliente MCP: a peça que conversa com o servidor, por mensagens padronizadas.
  • Host: o aplicativo onde a IA roda (Claude Code, Claude, Cursor…). Ele carrega o cliente.

As três coisas que um servidor MCP oferece

Mini glossário

PalavraEm palavras simples

Streamable HTTPO jeito de conversar pela rede. É o que usamos (protocol: STREAMABLE).

05Casos no restaurante

Para que serve um MCP num serviço de restaurante: ler, agir e juntar várias fontes.

Ler

  • “Quais pratos ficam abaixo de R$ 35 e são vegetarianos?”
  • “Quais restaurantes japoneses estão abertos agora?”
  • Para o cliente: “quero algo leve para o almoço”. A IA lê as descrições dos pratos.

Agir (com cuidado)

  • “Fecha o Sakura, a cozinha pegou fogo” (Exercício 1).
  • “Marca o temaki como indisponível, acabou o peixe” (usa o campo available, Exercício 7).
  • O dono resolve falando, sem abrir tela nenhuma.

Juntar fontes

  • “Quais os pratos mais vendidos do Bella Napoli esta semana?” cruza restaurante com pedidos.
  • “Algum pedido falhou hoje por prato indisponível?” cruza pedidos, cardápio e logs do Datadog.
Quando o MCP não ajuda Mostrar a lista de restaurantes na tela do app é pergunta fixa: o REST continua melhor, mais rápido e previsível. O MCP brilha quando a pergunta é solta e você não sabe antes qual ação vai precisar.
Segurança Quanto mais ações de escrever você dá para a IA, mais cuidado. Fechar um restaurante por engano custa dinheiro de verdade. Por isso o Exercício 3 separa as ferramentas de leitura das de escrita.

06Construir o MCP

Escolhemos o restaurant-service porque ele tem só consulta e um POST. Não tem PUT nem DELETE, então a turma decide o que a IA pode fazer.

Substitui restaurant-service/src/main/java/.../config/DataSeeder.java. O construtor de MenuItem não recebe o campo available, por isso há o método indisponivel(...). Os acentos ficaram de fora do código de propósito, como no seed original. Já está na main.

O seed só roda com o banco vazio A primeira linha (if (repository.count() > 0) return;) faz o seed não fazer nada se já existirem restaurantes. Por isso é preciso apagar o banco antes. Veja o próximo passo.

14Produção

Resumo do curso “Model Context Protocol: Advanced Topics” da Anthropic. Quatro coisas separam um servidor de estudo de um servidor de produção.

  1. O jeito de conversar. Local, pelo terminal (STDIO). Na rede, por HTTP (Streamable HTTP), que é o nosso caso.
  2. Com estado ou sem estado. Veja o desenho abaixo.
  3. Avisos em tempo real. Numa ferramenta lenta, o servidor manda logs e progresso para o usuário ver que está andando. Só funciona com estado.
  4. Sampling. O servidor pede para a IA do cliente pensar por ele. Assim o custo do modelo fica com o cliente, e não com o seu servidor.
O que o curso não cobre, mas é o nosso caso O /mcp não tem login, e o gateway também não valida JWT hoje. Para estudo local tudo bem; antes de publicar, precisa de autenticação. O Spring AI tem suporte a OAuth 2.0 e chave de API pelo projeto mcp-security.

15Armadilhas

  • Sem login. Nunca publique o /mcp assim.
  • Ferramenta que escreve é a que precisa de mais cuidado.
  • Descrição ruim, IA escolhendo errado. Escreva a descrição como se explicasse para um colega novo.
  • Validação só no controller não vale para a ferramenta MCP (experimento D).
  • Cache que nunca expira. Ao mudar dados por fora (seed, SQL), limpe o Redis.
  • Devolver entidade JPA. Aqui funciona porque o cardápio é EAGER e o MenuItem.restaurant tem @JsonIgnore. Em outro projeto, devolva um record próprio para evitar o erro de carregamento preguiçoso que a imagem v1 já teve.
  • Centavos. A IA pode ler 5800 como R$ 5.800. A descrição de ver_cardapio já avisa.
  • Teste direto na 8082, não pelo gateway.
